# Code Tiara 디자인 시스템 & 제품 규칙

> 이 문서는 **사람과 AI 모두를 위한 단일 기준**입니다. 데스크톱(Electron) 앱을 고치거나,
> 모바일/웹 버전을 새로 만들거나, 다른 AI 도구에 작업을 맡길 때 이 문서의 규칙을 따릅니다.
> 규칙을 바꾸는 PR은 **이 문서도 같은 PR에서 갱신**해야 합니다. (→ §15 프로세스)

마지막 갱신: 2026-09-14 · 적용 버전: 1.7.5+

---

## 1. 제품 한 줄 정의

**Code Tiara**는 "항상 옆에 떠 있는 작은 할 일 보드"입니다.
340×600 크기의 미니 창에서 카테고리별 할 일을 관리하고, 카테고리를 스티키 노트처럼
떼어내(팝아웃) 화면 위에 고정하고, 포모도로 타이머로 집중합니다.
Firebase 로그인으로 기기 간 동기화되며, 게스트 모드로 로그인 없이도 쓸 수 있습니다.

핵심 가치 순서: **① 작고 가볍게 ② 감성적이지만 방해되지 않게 ③ 키보드로도 빠르게**

### 3-2. 카테고리 색 (사용자 선택)

`src/constants.js`의 두 표를 **항상 짝으로** 사용합니다.

| key | `CATEGORY_HUES` (배경·라인, Tailwind 200단계) | `CATEGORY_ICON_HUES` (아이콘·텍스트, 400단계) |
|---|---|---|
| red / princess | `#FBCFE8` | `#FB7185` |
| blue / cyan | `#BAE6FD` | `#38BDF8` |
| green / mint / emerald | `#BBF7D0` | `#4ADE80` |
| yellow | `#FDE68A` | `#FBBF24` |
| purple | `#E9D5FF` | `#C084FC` |

파생 색 규칙:
- **카드 헤더 밴드** = `hexToRgba(hue, 0.45)` — 흰 카드 위에 45% 색 띠. 공책 인덱스 탭처럼 카테고리를 알리는 유일한 큰 색면.
- **카드 몸통은 항상 흰색.** 카드 배경에 투명 `rgba()`를 쓰지 않는다 — 팝아웃 창이 투명이라 바탕화면이 비친다 (실제 재현).
- 카드 테두리(전체 모드) = `CATEGORY_HUES[hue]` 2px. 행 테두리 = `--border-idle`, hover = `--border-hover`(카테고리 원색).
- CSS 변수 `--c-bg`(연한 배경), `--c-light`/`--c-light-rgb`(라인), `--c-dark`(진한 텍스트), `--border-idle`/`--border-hover`, `--icon-color`가 카드 안에서 주입되므로, 카드 내부 컴포넌트는 hex를 직접 쓰지 말고 이 변수를 쓴다.

## 4. 타이포그래피

| 테마 | 본문 | 제목 | 비고 |
|---|---|---|---|
| Princess | Gamja Flower (`font-gamja`) | Gaegu | 기본 1.05rem, `font-bold`. 사용자가 설정에서 Pretendard·Gaegu·Jua·Single Day 등으로 교체 가능 |
| Developer | monospace (`font-mono`) | 동일 | |
| Excel | 시스템 sans | 동일 | |

- 기본 텍스트 크기 **14px**, 사용자가 5단계(작게~아주크게)로 조절. 컴포넌트는 `getTextSizeClass(fontSize)`를 존중해야 한다.
- **DPI 규칙.** `-webkit-font-smoothing: antialiased`(회색조 AA)와 Princess의 가짜 굵기 `text-stroke 0.6px`는 **1.5x 이상(Retina)에서만**. 1x 외장 모니터에서는 회색조 AA가 글자를 가늘고 흐리게, 서브픽셀 스트로크는 번지게 만들어 "살짝 흐린" 인상을 준다 → 1x에서는 macOS 서브픽셀 AA + 브라우저 합성 볼드(정수 픽셀)를 쓴다. 모바일도 같은 기준(대부분 2x 이상이므로 Retina 규칙).
- 한 화면에 **폰트 패밀리는 최대 2개**(본문 + 제목). 로그인 화면의 `Inter` 하드코딩 같은 예외를 더 만들지 않는다.
- **테마 폰트 3종은 앱에 번들**되어 네트워크 없이 항상 같은 모양으로 나온다: `public/fonts/fonts.css`(`index.html`에서 링크)
  - Pretendard v1.3.9 가변 폰트 1개 (`public/fonts/pretendard/`, weight 45–920)
  - Gamja Flower, Gaegu 400/700 — Google Fonts와 동일한 **unicode-range 슬라이스**(`public/fonts/gamja-flower/` 93개, `public/fonts/gaegu/` 178개). 한글 11,172자 전부 커버하되 화면에 쓰인 범위의 파일만 로드된다. 총 ≈4.8MB.
  - 나머지 선택 폰트(Nanum Gothic/Myeongjo/Pen Script, Jua, Dongle, Single Day)는 `src/index.css`의 Google Fonts `@import`로 네트워크 로드 — 오프라인이면 대체 폰트.
  - 폰트를 추가/갱신할 때: Google Fonts CSS를 Chrome UA로 받아 `fonts.gstatic.com` URL을 로컬 경로로 치환해 `fonts.css`에 붙이고, 각 폰트 폴더에 `OFL.txt`/`LICENSE.txt`를 함께 둔다. 모바일 버전도 같은 파일을 그대로 쓸 수 있다.

## 5. 아이콘

1. **UI 크롬 아이콘은 lucide-react만.** 메뉴, 버튼, 헤더, 설정, 온보딩, 배지 — 전부.
2. **이모지가 허용되는 곳은 두 군데만**:
   - 카테고리 아이콘 (사용자가 고르는 콘텐츠, `getIcon()` 매퍼)
   - 문장 끝 말투 (`알림 내용 🧁`, `Code Tiara 💖`)
3. 크기: 메뉴·설정 항목 `w-3.5 h-3.5`, 카드 헤더 `w-4 h-4`(미니 `w-3 h-3`), 로고 `w-7 h-7`, 온보딩 히어로 `w-10 h-10`.
4. 아이콘만 있는 버튼은 반드시 `aria-label` 또는 `title`.
5. 테마 아이콘은 `THEME_CONFIG[key].themeIcon`에 **lucide 이름**('crown' | 'code' | 'table')을 넣고 `SettingsPanel`의 `ThemeIcon`으로 렌더한다. 이모지 문자열을 넣지 않는다.

## 6. 표면과 위계 (Surfaces)

> 원칙: **흰 카드 위에 카테고리 색 헤더 밴드, 그 아래 테두리 있는 흰 행.** 공책·스티커 메모 감성이 Princess의 정체성이다.
> 한 화면에서 시각적 층은 최대 3개(창 → 카드 → 행).

| 레벨 | 무엇 | Princess 스타일 |
|---|---|---|
| L0 | 창 | 창 = 카드. `#FFFCFD` 배경, `#FFC0CB` 2px 테두리, 16px 라운드, **그림자 없음**(OS 그림자 끔 §12, CSS 그림자도 사용자 선택으로 끔). 여백+그림자 메커니즘(`WINDOW_INSET`, `theme.windowShadow`)은 코드에 남아 있고 현재 0 |
| L1 | 카테고리 카드 | **흰색.** 전체 모드: 카테고리 색 2px 테두리, 라운드 20px, `shadow-sm`. 미니 모드: 테두리 없이 `shadow-[0_4px_10px_rgba(255,182,193,0.4)]`, 라운드 15px |
| L1-헤더 | 카드 헤더 밴드 | `hexToRgba(hue, 0.45)` 배경, 전체 모드에선 점선 하단 구분선 (`border-b-2 border-dashed`) |
| L2 | 할 일 행 | 흰색, `--border-idle` 1px 테두리, 라운드 16px, `shadow-sm`. hover 시 테두리가 `--border-hover`(원색)로 |
| L2 | 빠른 추가 폼 · 인라인 수정 폼 | `from-[var(--c-bg)] to-white` 그라데이션 + `--c-light-rgb` 1px 테두리, 라운드 18–24px |
| 입력 필드 | 폼 안의 인풋 | 흰 배경 + `--c-light` 1px 테두리 |

주의:
- 카드·헤더·행 어디에도 **투명 배경을 쓰지 않는다** (팝아웃 창 투명 → 바탕화면 비침).
- 팝아웃 스티키 노트 = 카드 2px 테두리 + 45% 색 헤더, 본 창과 같은 규칙.
- Developer / Excel 테마는 각자의 관습(1px 회색 라인, 직각)을 따르며 이 규칙의 적용 대상이 아니다.
- 2026-09-14에 "테두리 대신 톤"(파스텔 카드 + 테두리 없는 행) 시안을 실제 화면에서 검토했으나 **기존 디자인을 유지**하기로 결정 (→ §16). 다시 제안할 때는 그 로그를 먼저 읽을 것.

## 8. 레이아웃 모드

| 모드 | 조건 | 구조 |
|---|---|---|
| **미니** | 창 폭 `< 450px` (기본 창 340×600) | 단일 열, 카드 세로 스택. 모바일 레이아웃의 원본 |
| **전체** | 창 폭 `≥ 450px` | 카드 **그리드**: `repeat(auto-fill, minmax(280px, 1fr))`, 카드 상단 정렬, 카테고리가 열을 넘으면 줄바꿈 (가로 스크롤 금지) |
| **팝아웃** | `?popout=<categoryId>` 또는 `timer` / `onboarding` | 카테고리 하나 = 창 하나. 내용 높이에 맞춰 창 크기 자동. 항상 위 옵션 |

- **카드 안의 반응형은 창 폭이 아니라 카드 폭 기준**이다. 카테고리 카드가 `container-type: inline-size`이고, 카드 내부(할 일 행·추가/수정 폼·팝아웃 플레이스홀더)는 `sm:` 대신 `[@container(min-width:560px)]:` 변형을 쓴다. 전체 모드 그리드에서 카드는 400px 남짓이라 창 폭 기준 `sm:`을 쓰면 가로 배치가 강제돼 폼이 뭉개진다 (2026-09-14 재현).
- 미니↔전체 전환은 메뉴에서 수동으로도, 창 리사이즈로도 일어난다. 두 경로가 같은 상태(`isMiniMode`)를 바꿔야 한다.
- 팝아웃된 카테고리는 본 창에서 **플레이스홀더(160px, "외출 중")**로 남기고 "보드 데려오기"로 복귀시킨다.
- **무엇이 기기별이고 무엇이 클라우드 동기화인가**
  - 클라우드(Firestore `users/{uid}`): 할 일·카테고리 데이터, 취향 설정(테마·글꼴·글자 크기·타이머 시간·보드 제목·필터).
  - **기기별(이 PC에만)**: 어떤 카테고리를 팝아웃/핀 했는지(`localStorage`), 본 창의 위치·크기, 각 팝아웃 창의 위치(`userData/window-state.json`, 메인 프로세스). "이 책상 위 배치"는 다른 PC와 무관하다. 저장된 위치가 연결된 모니터 밖이면 무시하고 기본 위치(본 창 옆)로 띄운다.
  - 모바일 대응: 위젯 배치 = 기기별, 데이터 = 동기화 — 같은 구분.

## 9. 컴포넌트 규칙

### 카테고리 카드
- 헤더: `[아이콘] [제목] … [+ 추가] [팝아웃] [완료/전체 카운터]`. 순서 고정.
- 제목 색·아이콘 색 = `CATEGORY_ICON_HUES[hue]`.
- 빈 카테고리는 헤더만 남기고 최소 높이로 접힌다 (빈 상태 문구 없음).

### 할 일 행
- `[체크 원형] [텍스트] [시간·반복·알림 메타] … [hover: 복제 · 수정 · 삭제]`
- 완료 시 텍스트 취소선 + 50% 투명, 행은 그대로 (사라지지 않음). "완료 항목 정리"로만 삭제.
- 행 텍스트 클릭 = 완료 **토글**(다시 클릭하면 복귀). 실수해도 되돌릴 수 있으므로 의도된 동작. 모바일에서는 터치 오탭이 잦아 체크만 완료로 두는 것을 권장(§13).

### 빠른 추가 폼 (카드 안 인라인)
- 필드 순서: 할 일 → 상세 메모 → (날짜 · 반복) → (시 : 분 · AM/PM · 알림)
- 340px에서 옵션 행은 **줄바꿈 허용**(`flex-wrap`). 잘림 금지.
- placeholder: 새 항목은 `app.add_placeholder`, 수정은 `app.edit_placeholder`. 섞어 쓰지 않는다.
- 접혀 있을 때 `inert` — 보이지 않는 인풋에 Tab 포커스가 가면 안 된다.
- 단축키: Enter 저장, Esc 취소. 버튼 라벨은 테마별(Princess 아이콘 / Developer `[ENTER]` `[ESC]` / Excel 텍스트) — 텍스트는 반드시 `t()`.

### 전역 단축키 빠른 추가
- `⌘⇧Space`(macOS) / `Ctrl+Shift+Space`(Windows) — 어떤 앱에 있든 창을 앞으로 가져와 **첫 번째 카테고리의 추가 폼**을 열고 인풋에 포커스. 메인 프로세스 `globalShortcut` → IPC `quick-add`.
- 기본 켜짐. 설정 → "빠른 추가 단축키" 토글로 끔. 설정값은 메인 프로세스가 `userData/quick-add-shortcut.json`에 보관해 렌더러 로드 전에도 적용된다.
- 다른 앱이 같은 조합을 쓰면 등록이 실패한다 → 설정에 빨간 안내 문구. 조합 변경(레코딩) UI는 아직 없음.
- 모바일 대응: 홈 화면 위젯 / 앱 아이콘 롱프레스 퀵 액션 "할 일 추가".

### 메뉴 (톱니 → 드롭다운)
- 항목: 전체/미니 모드 · 타이머 · 완료 항목 정리 · 전체 설정. lucide 아이콘 + 라벨.
- 설정 패널은 Esc로 닫힌다. 새 오버레이도 모두 Esc 닫기 지원.

### 알림 패널 (벨)
- 헤더: lucide `Bell` + "새 소식 (n)" · 오른쪽 "모두 지우기" 텍스트 버튼(밑줄 없음).
- 항목 = **제목 = 할 일 이름**(굵게 `font-black`, 1줄 말줄임) + 오른쪽 시각, 아래 줄에 **짧은 상태 문구**(11px, `font-medium`, slate-500 — 제목보다 한 단계 작고 연하게) ("마감 시간이에요", "마감 15분 전"). 할 일 이름을 따옴표로 문장 안에 넣지 않는다 — 340px에서 두 줄로 꺾여 읽기 어렵다.
- 타이머 알림도 같은 구조(제목 "집중 시간 종료" + 문구). 읽지 않음 표시는 카테고리 핑크 점, **무한 애니메이션 금지**.
- OS 알림도 동일: 제목 = 할 일 이름, 본문 = 상태 문구 (앱 이름은 OS가 붙인다).
- 알림 본문에는 이모지를 붙이지 않는다 (2026-09-14 사용자 결정 — 짧은 상태 문구만).

### 온보딩 (사용 설명서 팝아웃)
- 자동 노출은 **이 PC에서 한 번만**. 계정과 무관한 기기 플래그 `lumora_onboarding_completed`(+ 계정별 플래그)를 **여는 순간** 기록한다 — 게스트로 봤다가 로그인해도, 창을 OS로 닫아버려도 다시 뜨지 않는다. 클라우드에 올리지 않는다(§8 기기별 상태).
- 다시 보기는 설정 → 사용 가이드. 앱 초기화(localStorage 삭제) 후에는 다시 자동 노출된다 — 의도된 동작.

### 설정 패널
- 접이식 섹션. 순서: 테마 → 타이머·글꼴 → 데이터 백업/복원 → 카테고리 관리 → 언어 → (가이드 · 로그인/로그아웃 · 초기화) → 버전.
- 위험 동작(초기화, 계정 삭제)은 `dangerBtn` 스타일 + 확인 단계.
- 하단 액션 버튼(가이드 · 로그인/로그아웃 · 회원탈퇴 · 초기화)은 **`flex-wrap` 한 줄**, 버튼은 `whitespace-nowrap`. 폭이 모자라면 버튼 단위로 줄바꿈한다 — 글자를 쪼개 두 줄로 만들지 않는다 (한국어는 공백이 없어 "사용 가이 / 드"처럼 깨진다).
- **창 모드(미니/전체 모드) 유지**: 설정 패널 진입·이탈 시 `isMiniMode`를 임의로 토글하거나 강제하지 않는다. 설정 패널은 340px(미니)와 900px(전체) 양쪽 모두에서 자연스럽게 반응형으로 작동하며, 설정을 닫거나 다른 화면(로그인 모달, 가이드 등)으로 전환될 때 기존 창 모드와 크기를 온전히 보존한다.

### 로그인 / 회원가입
- 로고 = 브랜드 그라데이션 왕관 (흰 스쿼클, `shadow-float`), 워드마크 그라데이션.
- 기본 버튼 = `from-[#F48FB1] to-[#FF6B81]` 그라데이션, 흰 글자, 14px 라운드.
- 링크·체크박스 = `#FF6B81`. 게스트 모드 버튼은 항상 노출.

## 10. 카피 & i18n

1. **모든 사용자 노출 문자열은 `t()`**. 하드코딩 한국어/영어 금지. 변수·콜백 파라미터 이름으로 `t`를 쓰지 않는다 — i18n `t`를 가려 호출이 깨진다 (2026-09-14 알림 버그).
2. 키는 `ko.json`과 `en.json`에 **동시에** 추가. 섹션은 `settings` / `onboarding` / `app` / `auth` 네 개.
3. **기본 데이터(예시 할 일·카테고리 이름)는 i18n 키를 그대로 저장하고, 화면에 그릴 때 번역한다.** (`displaySampleText(t, text)` — `src/constants.js`)
   - 그래서 UI 언어를 바꾸면 예시 항목도 따라 바뀐다. 사용자가 예시를 수정하면 그 순간부터 일반 텍스트가 된다.
   - 텍스트를 화면에 내보내는 모든 지점(행, 헤더, 수정 인풋 초기값, 복제, 알림, 삭제 확인, 설정의 카테고리 목록)은 `display()`를 거친다. 새 지점을 추가하면 같은 헬퍼를 쓴다.
   - 예전 빌드가 번역된 텍스트나 원시 키를 저장해 둔 데이터는 로드 시 `normalizeSampleText`가 정확히 일치하는 경우에만 키로 되돌린다.
4. 문장은 짧게, 존댓말 "~해 주세요", 느낌표 최대 1개.
5. 말투 이모지는 문장 끝 1개까지 (§2, §5).

## 12. 모션

- 전환 200–300ms, `ease-in-out`. 오버레이 등장 `animate-in fade-in slide-in-from-bottom-4`.
- 기능이 아닌 장식 모션(회전, 무한 반복)은 온보딩 히어로에서만.
- 팝아웃 창 리사이즈는 콘텐츠 높이 합산으로 계산해 한 번에 적용 (깜빡임 방지: `show: false` → 리사이즈 → `show`).
- 투명·프레임 없는 창(본 창·팝아웃)은 **OS 창 그림자를 끈다**(`hasShadow: false`). 창 = 콘텐츠 + 2×`WINDOW_INSET` 투명 여백 + CSS 그림자(`theme.windowShadow`) 메커니즘이 있지만 **현재 `WINDOW_INSET = 0`** — 핑크 그림자가 너무 도드라진다는 사용자 판단으로 평평한 카드를 유지한다. 메인 프로세스의 모든 창 크기는 `withInset()`을 거치고(`WINDOW_INSET`), 렌더러는 `window.electron.windowInset`으로 같은 값을 받아 카드를 안쪽에 배치한다 — 렌더러↔메인 IPC의 크기 값은 항상 **콘텐츠 크기**다. macOS는 투명 창의 알파 가장자리에 1px 어두운 림을 그림자의 일부로 그리는데, 둥근 카드가 곧 창 가장자리라 Princess 연핑크 테두리 옆에서 검은 외곽선으로 보였다. 분리감은 테마 테두리(`#FFC0CB` 1.5px)가 담당한다. 그림자를 다시 켤 경우에만 아래 규칙이 적용된다.
- (그림자를 켠 창에 한해) **모양이 바뀐 뒤 `invalidateShadow()`** — macOS는 알파 모양으로 계산한 그림자를 스스로 갱신하지 않아, 리사이즈 전 직사각형 그림자가 둥근 모서리 밖에 검은 테두리로 남는다 (`refreshWindowShadow`, `main.js`).

## 14. 엔지니어링 규칙 (요약 — 상세는 `AGENTS.md`, `README.md`)

- 렌더러는 `contextIsolation: true`, `nodeIntegration: false`. 채널 목록(2026-09-14): send — 창 제어 3, 저장소 동기화 2, 팝아웃 6, `set-auto-launch`, `open-external` · invoke — `get-auto-launch`, `get/set-quick-add-shortcut` · receive — `auth-popup-closed`, `storage-changed`, `storage-clear`, `popout-closed`, `quick-add`. - 카테고리 색은 §3-2의 표와 `hexToRgba`로만 파생. 카드 배경은 항상 불투명.
- 메인 프로세스의 `console.log`는 stdout이 끊겨도 앱을 죽이지 않도록 EPIPE를 무시한다 — 유지.
