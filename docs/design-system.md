# Code Tiara 디자인 시스템 & 제품 규칙

> 이 문서는 **사람과 AI 모두를 위한 단일 기준**입니다. 데스크톱(Electron) 앱을 고치거나,
> 모바일/웹 버전을 새로 만들거나, 다른 AI 도구에 작업을 맡길 때 이 문서의 규칙을 따릅니다.
> 규칙을 바꾸는 PR은 **이 문서도 같은 PR에서 갱신**해야 합니다. (→ §15 프로세스)

마지막 갱신: 2026-09-14 · 적용 버전: 1.7.5+

---

## 1. 제품 한 줄 정의

**Code Tiara**는 "항상 옆에 떠 있는 작은 할 일 보드"입니다.
340×600 크기의 미니 창에서 카테고리별 할 일을 관리하고, 카테고리를 스티키 노트처럼
떼어내(팝아웃) 화면 위에 고정하고, 포모도로 타이머로 집중합니다.
Firebase 로그인으로 기기 간 동기화되며, 게스트 모드로 로그인 없이도 쓸 수 있습니다.

핵심 가치 순서: **① 작고 가볍게 ② 감성적이지만 방해되지 않게 ③ 키보드로도 빠르게**

| 항목 | 규칙 |
|---|---|
| 기본 테마 | **Princess.** 저장된 테마가 없으면 항상 Princess. Developer / Excel은 사용자가 고르는 *옵션 스킨*이며 브랜드를 대표하지 않는다 |
| 심볼 | 라인 스타일 왕관 (lucide `Crown`). 앱 아이콘은 흰 스쿼클 위 그라데이션 왕관 |
| 브랜드 그라데이션 | `#6FB4E6` (하늘) → `#B39DDB` (라벤더) → `#F28AB2` (핑크), 좌→우. 로고·워드마크·앱 아이콘에만 사용. 버튼/배경에는 쓰지 않는다 |
| 워드마크 | `CODE TIARA`, 대문자, `tracking-widest`, 브랜드 그라데이션 텍스트 (`bg-clip-text`) |

| 톤 & 매너 | 다정하고 짧게. 말투용 이모지(🧁 💖 👑)는 *문장 끝*에만, UI 아이콘 자리에는 절대 쓰지 않는다 (→ §5) |
| 검은색 금지 | 로그인 화면·버튼에 `bg-black`을 쓰지 않는다. 강조는 항상 Princess 핑크 계열 |

### 3-2. 카테고리 색 (사용자 선택)

`src/constants.js`의 두 표를 **항상 짝으로** 사용합니다.

| key | `CATEGORY_HUES` (배경·라인, Tailwind 200단계) | `CATEGORY_ICON_HUES` (아이콘·텍스트, 400단계) |
|---|---|---|
| red / princess | `#FBCFE8` | `#FB7185` |
| blue / cyan | `#BAE6FD` | `#38BDF8` |
| green / mint / emerald | `#BBF7D0` | `#4ADE80` |
| yellow | `#FDE68A` | `#FBBF24` |
| purple | `#E9D5FF` | `#C084FC` |

파생 색 규칙:
- **카드 배경** = `hexTint(hue, 0.16)` — 흰색과 섞은 **불투명** 파스텔. `rgba()` 투명 틴트를 쓰지 않는다 (팝아웃 창이 투명이라 바탕화면이 비친다).
- **팝아웃 헤더** = `hexToRgba(hue, 0.45)` (팝아웃 안에서만).
- CSS 변수 `--c-bg`(연한 배경), `--c-light`(라인), `--c-dark`(진한 텍스트)가 카드 안에서 주입되므로, 카드 내부 컴포넌트는 hex를 직접 쓰지 말고 이 변수를 쓴다.

## 4. 타이포그래피

| 테마 | 본문 | 제목 | 비고 |
|---|---|---|---|
| Princess | Gamja Flower (`font-gamja`) | Gaegu | 기본 1.05rem, `font-bold`. 사용자가 설정에서 Pretendard·Gaegu·Jua·Single Day 등으로 교체 가능 |
| Developer | monospace (`font-mono`) | 동일 | |
| Excel | 시스템 sans | 동일 | |

- 기본 텍스트 크기 **14px**, 사용자가 5단계(작게~아주크게)로 조절. 컴포넌트는 `getTextSizeClass(fontSize)`를 존중해야 한다.
- 한 화면에 **폰트 패밀리는 최대 2개**(본문 + 제목). 로그인 화면의 `Inter` 하드코딩 같은 예외를 더 만들지 않는다.
- 웹폰트는 현재 CDN(Google Fonts, jsDelivr)에서 로드 → 오프라인 첫 실행 시 대체 폰트가 뜬다. **Pretendard는 로컬 번들 예정**(→ §16 결정 로그).

## 5. 아이콘

1. **UI 크롬 아이콘은 lucide-react만.** 메뉴, 버튼, 헤더, 설정, 온보딩, 배지 — 전부.
2. **이모지가 허용되는 곳은 두 군데만**:
   - 카테고리 아이콘 (사용자가 고르는 콘텐츠, `getIcon()` 매퍼)
   - 문장 끝 말투 (`알림 내용 🧁`, `Code Tiara 💖`)
3. 크기: 메뉴·설정 항목 `w-3.5 h-3.5`, 카드 헤더 `w-4 h-4`(미니 `w-3 h-3`), 로고 `w-7 h-7`, 온보딩 히어로 `w-10 h-10`.
4. 아이콘만 있는 버튼은 반드시 `aria-label` 또는 `title`.
5. 테마 아이콘은 `THEME_CONFIG[key].themeIcon`에 **lucide 이름**('crown' | 'code' | 'table')을 넣고 `SettingsPanel`의 `ThemeIcon`으로 렌더한다. 이모지 문자열을 넣지 않는다.

## 6. 표면과 위계 (Surfaces)

> 원칙: **테두리가 아니라 톤 차이로 층을 구분한다.** 한 화면에서 시각적 층은 최대 3개.

| 레벨 | 무엇 | Princess 스타일 |
|---|---|---|
| L0 | 창 배경 | `#FFFCFD`, 창 자체가 `#FFC0CB` 1.5px 테두리 + 16px 라운드 (frameless) |
| L1 | 카테고리 카드 | `hexTint(hue, 0.16)` 불투명 파스텔, **테두리·그림자 없음**, 라운드 18px(미니)/20px(전체), 안쪽 여백 `p-1.5` |
| L2 | 할 일 행 · 빠른 추가 폼 · 인라인 수정 폼 | 흰색, 라운드 12px, `shadow-[0_1px_3px_rgba(255,150,170,0.18)]`, **테두리 없음**. hover 시 그림자만 진해짐 |
| 입력 필드 | 폼 안의 인풋 | 흰 배경 + `--c-light` 1px 테두리 — 입력 가능함을 알리는 유일한 테두리 |

예외:
- **팝아웃 스티키 노트**는 독립된 떠 있는 창이므로 카테고리 색 2px 테두리 + 45% 색 헤더를 유지한다.
- Developer / Excel 테마는 각자의 관습(1px 회색 라인, 직각)을 따르며 이 규칙의 적용 대상이 아니다.

## 8. 레이아웃 모드

| 모드 | 조건 | 구조 |
|---|---|---|
| **미니** | 창 폭 `< 450px` (기본 창 340×600) | 단일 열, 카드 세로 스택. 모바일 레이아웃의 원본 |
| **전체** | 창 폭 `≥ 450px` | 카드 **그리드**: `repeat(auto-fill, minmax(280px, 1fr))`, 카드 상단 정렬, 카테고리가 열을 넘으면 줄바꿈 (가로 스크롤 금지) |
| **팝아웃** | `?popout=<categoryId>` 또는 `timer` / `onboarding` | 카테고리 하나 = 창 하나. 내용 높이에 맞춰 창 크기 자동. 항상 위 옵션 |

- 미니↔전체 전환은 메뉴에서 수동으로도, 창 리사이즈로도 일어난다. 두 경로가 같은 상태(`isMiniMode`)를 바꿔야 한다.
- 팝아웃된 카테고리는 본 창에서 **플레이스홀더(160px, "외출 중")**로 남기고 "보드 데려오기"로 복귀시킨다.

## 9. 컴포넌트 규칙

### 카테고리 카드
- 헤더: `[아이콘] [제목] … [+ 추가] [팝아웃] [완료/전체 카운터]`. 순서 고정.
- 제목 색·아이콘 색 = `CATEGORY_ICON_HUES[hue]`.
- 빈 카테고리는 헤더만 남기고 최소 높이로 접힌다 (빈 상태 문구 없음).

### 할 일 행
- `[체크 원형] [텍스트] [시간·반복·알림 메타] … [hover: 복제 · 수정 · 삭제]`
- 완료 시 텍스트 취소선 + 50% 투명, 행은 그대로 (사라지지 않음). "완료 항목 정리"로만 삭제.
- 알려진 이슈: 행 텍스트 클릭 = 완료 토글. 실수 완료가 잦으면 클릭=열기 / 체크=완료로 분리 검토 (→ §16).

### 빠른 추가 폼 (카드 안 인라인)
- 필드 순서: 할 일 → 상세 메모 → (날짜 · 반복) → (시 : 분 · AM/PM · 알림)
- 340px에서 옵션 행은 **줄바꿈 허용**(`flex-wrap`). 잘림 금지.
- placeholder: 새 항목은 `app.add_placeholder`, 수정은 `app.edit_placeholder`. 섞어 쓰지 않는다.
- 접혀 있을 때 `inert` — 보이지 않는 인풋에 Tab 포커스가 가면 안 된다.
- 단축키: Enter 저장, Esc 취소. 버튼 라벨은 테마별(Princess 아이콘 / Developer `[ENTER]` `[ESC]` / Excel 텍스트) — 텍스트는 반드시 `t()`.

### 메뉴 (톱니 → 드롭다운)
- 항목: 전체/미니 모드 · 타이머 · 완료 항목 정리 · 전체 설정. lucide 아이콘 + 라벨.
- 설정 패널은 Esc로 닫힌다. 새 오버레이도 모두 Esc 닫기 지원.

### 설정 패널
- 접이식 섹션. 순서: 테마 → 타이머·글꼴 → 데이터 백업/복원 → 카테고리 관리 → 언어 → (가이드 · 로그인/로그아웃 · 초기화) → 버전.
- 위험 동작(초기화, 계정 삭제)은 `dangerBtn` 스타일 + 확인 단계.

### 로그인 / 회원가입
- 로고 = 브랜드 그라데이션 왕관 (흰 스쿼클, `shadow-float`), 워드마크 그라데이션.
- 기본 버튼 = `from-[#F48FB1] to-[#FF6B81]` 그라데이션, 흰 글자, 14px 라운드.
- 링크·체크박스 = `#FF6B81`. 게스트 모드 버튼은 항상 노출.

## 10. 카피 & i18n

1. **모든 사용자 노출 문자열은 `t()`**. 하드코딩 한국어/영어 금지 (테마 장식 문자 `>_`, `[ESC]` 제외).
2. 키는 `ko.json`과 `en.json`에 **동시에** 추가. 섹션은 `settings` / `onboarding` / `app` / `auth` 네 개.
3. 새 기본 데이터(예시 할 일, 카테고리 이름)도 키로 만든다 — 렌더 시점에 `t()`가 안 잡히면 키 문자열이 그대로 보인다.
4. 문장은 짧게, 존댓말 "~해 주세요", 느낌표 최대 1개.
5. 말투 이모지는 문장 끝 1개까지 (§2, §5).

## 11. 접근성

- 아이콘만 있는 버튼: `aria-label`. 체크 원형, 드래그 핸들 포함.
- 숨긴 영역: `inert` (opacity 0으로만 숨기지 않는다).
- 모든 오버레이: Esc 닫기, 포커스가 오버레이 안에 머물기.
- 색만으로 상태를 전달하지 않기 — 완료는 취소선+체크, 카테고리는 아이콘+색.
- 최소 터치/클릭 타깃 28px(데스크톱) / 44px(모바일).

---

## 12. 모션

- 전환 200–300ms, `ease-in-out`. 오버레이 등장 `animate-in fade-in slide-in-from-bottom-4`.
- 기능이 아닌 장식 모션(회전, 무한 반복)은 온보딩 히어로에서만.
- 팝아웃 창 리사이즈는 콘텐츠 높이 합산으로 계산해 한 번에 적용 (깜빡임 방지: `show: false` → 리사이즈 → `show`).

## 13. 모바일 버전을 만들 때

| 데스크톱 | 모바일 대응 |
|---|---|
| 미니 모드 (340px 단일 열) | **그대로 모바일 기본 화면.** 카드·행·폼 규칙 §6–§9 동일 |
| 전체 모드 그리드 | 태블릿 가로에서만. 폰에서는 미니 모드 |
| 팝아웃 스티키 노트 | 홈 화면 위젯 또는 바텀 시트. "항상 위" 개념은 위젯으로 대체 |
| 커스텀 타이틀 바(신호등) | 없음. 시스템 상태바 + 안전 영역(safe-area) 여백 |
| 트레이 아이콘 | 없음. 알림은 OS 로컬 알림 |
| hover로 나타나는 행 액션(복제·수정·삭제) | 스와이프 액션 또는 길게 누르기. hover 의존 금지 |
| 행 텍스트 클릭 = 완료 | 모바일에서는 **체크만 완료**, 텍스트 탭 = 열기 (실수 방지) |
| 창 테두리 `#FFC0CB` | 없음. 배경 `#FFFCFD` 전체 |
| 폰트 | Pretendard/Gamja Flower 번들. 시스템 폰트 폴백 |
| 데이터 | 동일 Firestore 구조 `users/{uid}/...` + 동일 규칙 파일 `firestore.rules` |

## 14. 엔지니어링 규칙 (요약 — 상세는 `AGENTS.md`, `README.md`)

- 렌더러는 `contextIsolation: true`, `nodeIntegration: false`. Electron API는 `public/preload.js`의 `window.electron`만. **채널 allow-list**에 없는 IPC는 차단된다 — 채널 추가 시 `main.js` 핸들러 + `preload.js` 목록 둘 다 갱신.
- 프로덕션 origin `http://127.0.0.1:51283`은 **절대 바꾸지 않는다** (localStorage/IndexedDB가 묶여 있음).
- 테마 스타일은 `src/constants/themeConfig.js`에 모으고, 컴포넌트에서는 `theme.*` 토큰을 쓴다. 새 테마 = 이 파일에 객체 추가 + `themeIcon`(lucide 이름) + 온보딩 칩.
- 카테고리 색은 §3-2의 함수로만 파생 (`hexTint`, `hexToRgba`).
- 메인 프로세스의 `console.log`는 stdout이 끊겨도 앱을 죽이지 않도록 EPIPE를 무시한다 — 유지.

## 15. 프로세스 규칙

1. **항목 하나 = 브랜치 하나 = PR 하나.** 디자인 변경과 버그 수정을 한 PR에 섞지 않는다.
2. UI를 바꾸는 PR은 **전/후 스크린샷**을 340×600(미니)과 900×650(전체)에서 찍어 PR에 남긴다. Princess가 기준, 다른 테마는 깨지지 않는지만 확인.
3. 머지 전 필수 검증: `npm run build` → `CODE_TIARA_ENV=production npx electron .` 스모크(브리지·팝아웃·저장소 동기화·렌더러 예외 0) → 3개 테마 눌러보기.
4. 규칙이 생기거나 바뀌면 **이 문서 §16에 날짜와 이유를 적고**, 해당 절을 고친다.
5. 디자인 시안은 코드 전에 **실제 앱 위에 CSS로 얹어 2안 이상 비교**하고 사용자가 고른 뒤 구현한다.
